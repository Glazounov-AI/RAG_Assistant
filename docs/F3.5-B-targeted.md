# F3.5-B — Targeted retrieval

POST /query accepts optional `sources`: 1–20 distinct exact indexed basenames (case sensitive), each at most 255 characters. No paths or glob matching. Omission/null preserves legacy routing and cache behavior. Explicit sources select semantic retrieval within the current mode only, bypassing catalog routing and both cache reads and writes. The Chroma metadata filter is applied before ranking. Missing sources are not substituted; if no matching chunks exist, return HTTP 200, strategy targeted, model local-no-context, empty retrieved_sources and no LLM generation. If no requested source exists, embedding is also skipped. If only some sources exist, only those available are searched; this is not a completeness guarantee. Unexpected returned source fails closed. Existing authentication and rate limits remain. This filter is not an authorization mechanism. No Service Desk business rules, new dependencies or GigaChat changes.

Example: {"query":"VPN connected, resources unavailable","mode":"it_service_desk","sources":["EXACT_INDEXED_FILENAME.md"]}. Replace filename with the actual indexed basename. top_k remains profile-defined. Generated answers are not independently verified. Service Desk must handle empty sources and enforce diagnostic decisions itself.

Validation: syntax compilation performed; runtime tests require installed project dependencies and Python 3.14.4. No paid API calls performed. Run full pytest before integration.
