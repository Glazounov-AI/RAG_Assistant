## F2.2 agreed design (not implemented in F2-final)

- Keep SQLite and ChromaDB for MVP; defer PostgreSQL migration. Separate storage access from business logic where practical.
- Optional structured document header with object ID, type, title, summary and profile-defined attributes; build a profile-scoped registry during indexing. Validate identity and handle updates/deletions. Legacy documents remain searchable.
- Query Router selects retrieval strategy, not the user's business category. Preserve the original question. Default semantic search; explicit list/count/filter use structured data, not top-k chunks. Never present partial results as exhaustive. Paginate large lists.
- Extensible strategy registry with a common interface; profile configuration controls enabled strategies, default and router enablement. Validate configuration at startup. No fixed strategy count. New implementations must be registered before activation.
- Initial strategies: semantic, list, count, filter. Use deterministic routing for clear requests without mandatory extra LLM calls. Ambiguous requests fall back to semantic search or clarification, preserving safety and completeness constraints.
- Domain classification, escalation and ticket logic belong to IT Service Desk (F3), not the generic retrieval router. Help the user before formalizing the request; classification may assist retrieval but must not replace the answer.
- Include strategy/configuration and registry revision in cache identity where applicable. Test 100-object enumeration, profile isolation, legacy profiles and normal VPN assistance. No separate paid A/B experiment required now.
