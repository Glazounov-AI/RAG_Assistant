# RAG Assistant — интеллектуальный поиск по базе знаний

**Тип проекта:** AI-ассистент, RAG, поиск по документам, HTTP API
**Статус:** действующая демонстрационная API-версия; расширение для сайта-портфолио находится в разработке
**Репозиторий:** https://github.com/Glazounov-AI/RAG_Assistant
**Демонстрационный API:** https://ragassistant-production-6923.up.railway.app/docs

## Назначение

RAG Assistant — система, которая отвечает на вопросы пользователей с опорой на документы базы знаний.

В отличие от обычного чат-бота, ассистент сначала ищет релевантную информацию в загруженных материалах, а затем использует найденный контекст для формирования ответа языковой моделью.

Проект подходит для демонстрации подхода к созданию корпоративных AI-ассистентов, систем технической поддержки и интеллектуального поиска по внутренней документации.

## Какие задачи решает

- Поиск ответов в текстовых документах и базе знаний.
- Обработка вопросов на естественном языке.
- Использование найденного контекста при генерации ответов.
- Повторное использование ранее сформированных ответов через кеш.
- Регистрация запросов и времени обработки.
- Предоставление функциональности через HTTP API для интеграции с другими приложениями.

## Технологии

- Python и FastAPI — серверное приложение и HTTP API.
- OpenAI GPT-4o-mini — генерация ответов в редакции `assistant_api`.
- OpenAI `text-embedding-3-small` — создание эмбеддингов.
- ChromaDB — векторное хранилище и поиск релевантных фрагментов.
- SQLite — кеширование, журналирование и ограничение частоты запросов.
- Railway — размещение демонстрационного HTTP API.
- GigaChat — альтернативная самостоятельная редакция ассистента.

## Архитектура

Проект содержит две самостоятельные редакции:

**assistant_api (OpenAI)**

Поддерживает консольный интерфейс, HTTP API, кеширование, логирование и оценку качества RAG с использованием RAGAS.

**assistant_giga (GigaChat)**

Использует GigaChat для генерации ответов и эмбеддингов. Имеет собственные настройки, векторное хранилище, кеш и журнал запросов. HTTP API в этой редакции не реализован.

## Принцип работы

1. Пользователь задаёт вопрос.
2. Система проверяет наличие подходящего ответа в кеше.
3. Если ответа нет, создаётся эмбеддинг вопроса.
4. ChromaDB находит релевантные фрагменты документов.
5. Найденный контекст передаётся языковой модели.
6. Модель формирует ответ с учётом предоставленных материалов.
7. Результат сохраняется в кеше и возвращается пользователю.
8. Информация об обработке запроса записывается в SQLite-журнал.

## Реализованные возможности

В проекте реализованы:

- Индексация текстовых документов.
- Семантический поиск по ChromaDB.
- Кеширование ответов в SQLite.
- Логирование запросов, источника обращения, времени обработки и использования кеша.
- HTTP API с маршрутами `/health` и `/query`.
- Проверка корректности пользовательских запросов.
- Ограничение частоты запросов по режимам.
- Опциональная авторизация HTTP API через `X-API-Key`.
- Оценка качества RAG с использованием RAGAS.

## Два режима работы HTTP API

В ветке `feature/multi-knowledge-base` реализовано разделение на две базы знаний.

**support** — режим технической поддержки. Использует коллекцию ChromaDB `api_rag_collection`.

**portfolio** — режим ответов на вопросы о проектах, услугах и технических возможностях Glazounov AI Lab. Использует отдельную коллекцию `portfolio_kb` и специальный системный промпт.

Режим выбирается параметром `mode` в запросе к API. Для каждого режима предусмотрены отдельные настройки длины запроса и частоты обращений.

Подготовка документов для `portfolio_kb` и интеграция этого режима с сайтом продолжаются.

## Развёртывание и проверка

Демонстрационная версия `assistant_api` развёрнута на Railway.

Для постоянного хранения SQLite и ChromaDB используется Railway Volume. Проверены работоспособность HTTP API, обработка запросов, использование кеша и сохранность данных при развёртывании.

Новые возможности ветки `feature/multi-knowledge-base` пока не перенесены в production.

## Ограничения

- Качество ответов зависит от полноты и актуальности документов.
- Если в базе знаний нет необходимых сведений, ассистент не должен придумывать факты.
- Проект является демонстрацией технических возможностей и не заявляется как внедрённое решение конкретного заказчика.
- Интеграция с сайтом-портфолио и наполнение отдельной базы знаний находятся в работе.

## Возможные применения

Архитектура может быть адаптирована для:

- корпоративных баз знаний;
- внутренней технической поддержки;
- справочных AI-ассистентов;
- поиска по документации продуктов и услуг;
- AI-консультантов на сайтах.

Для конкретного внедрения необходимы подготовка документов, настройка доступа, тестирование качества ответов и интеграция с инфраструктурой заказчика.
